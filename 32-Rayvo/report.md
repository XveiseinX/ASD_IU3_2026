## Задача 1. Максимум и минимум

Дан массив из n целых чисел. Найти минимальный и максимальный элементы массива. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву.
`min` и `max` инициализируются первым элементом массива.
На каждой итерации текущий элемент сравнивается с `min` и `max`; если он меньше `min` — обновляется `min`, если больше `max` — обновляется `max`.
Сортировка и дополнительные структуры данных не используются.
Пустой массив и `null` считаются некорректным входом, выбрасывается `IllegalArgumentException`.
Результат возвращается в виде неизменяемой пары `(min, max)`.

### Асимптотика

[Расчет асимптотики задачи 1](asymptotics.md#задача-1-максимум-и-минимум).

Время: O(n).
Дополнительная память: O(1) для переменных min и max.

### Проверки

- `7 3 12 1 9` → (1, 12): неотсортированный массив.
- `17` → (17, 17): один элемент.
- `6 6 6 6` → (6, 6): все элементы равны.
- `2 4 6 8 10` → (2, 10): отсортированный по возрастанию.
- `10 8 6 4 2` → (2, 10): отсортированный по убыванию.
- `-5 -20 -3 -12` → (-20, -3): отрицательные числа.
- `-4 7 0 12 -9` → (-9, 12): смешанные положительные и отрицательные.
- пустой массив → исключение: недопустимый вход.
- `null` → исключение: недопустимый вход.

## Задача 2. Индекс первого вхождения

Дан массив из n целых чисел и число x. Найти индекс первого элемента, равного x. Если такого нет — вывести -1. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву слева направо.
На каждом шаге текущий элемент сравнивается с x; при первом совпадении сразу возвращается индекс `i`.
Если цикл завершился без совпадений — возвращается `-1`.
Поскольку проход идёт слева направо и возврат происходит при первом же совпадении, гарантированно находится именно первое вхождение, а не любое.
Массив `null` трактуется как «элемент не найден» и даёт `-1`.

### Асимптотика

[Расчет асимптотики задачи 2](asymptotics.md#задача-3-подсчёт-вхождений).

Время: O(n).
Дополнительная память: O(1) — только счётчик цикла.

### Проверки

- `5 15 8 3 15 2 11` → 2: элемент 15 на позиции 2.
- `5 3 8 3 15 3 11` → 1: число 3 встречается на позициях 1 и 3, ответ — первое вхождение.
- `5 8 8 3 15 2 11` → 0: элемент первый.
- `5 11 8 3 15 2 11` → 4: элемент последний.
- `5 7 8 3 15 2 11` → -1: элемента нет.
- `1 25 25` → 0: один элемент, найден.
- `1 7 25` → -1: один элемент, не найден.
- `4 6 6 6 6 6` → 0: все элементы равны, первое вхождение.
- `4 -2 -8 -14 -2 -6` → 2: отрицательные числа.
- `5 5 -3 5 0 8 -7` → 1: смешанные знаки.
- `5 0 -3 5 0 8 -7` → 2: поиск нуля.
- пустой массив → -1: недопустимый вход трактуется как «не найдено».
- `null` → -1: недопустимый вход трактуется как «не найдено».

## Задача 3. Подсчёт вхождений

Дан массив из n целых чисел и число x. Найти количество элементов, равных x. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву.
Счётчик `count` инициализируется нулём.
Для каждого элемента проверяется равенство с `x`; при совпадении `count` увеличивается на единицу.
В отличие от поиска первого вхождения (задача 2), досрочный выход невозможен: нужно просмотреть весь массив, чтобы учесть все вхождения.
Массив `null` и пустой массив дают `0` — по условию возвращается количество элементов, а не признак «найдено/не найдено».

### Асимптотика

[Расчет асимптотики задачи 3](asymptotics.md#задача-2-индекс-первого-вхождения).

Время: O(n).
Дополнительная память: O(1) — только счётчик count.

### Проверки

- `5 9 4 9 2 7 5` → 1: одно вхождение.
- `5 4 4 9 4 2 4` → 3: три вхождения.
- `5 7 4 9 4 2 4` → 0: элемента нет.
- `4 6 6 6 6 6` → 4: все элементы равны.
- `1 25 25` → 1: один элемент, найден.
- `1 7 25` → 0: один элемент, не найден.
- `5 -8 -8 -14 -8 -2 -8` → 3: отрицательные числа.
- `7 5 -3 5 0 8 5 -7 5` → 3: смешанные знаки.
- `5 0 0 3 0 8 0` → 3: поиск нуля.
- `5 9 9 1 2 3 9` → 2: вхождения по краям.
- пустой массив → 0: недопустимый вход трактуется как «нет вхождений».
- `null` → 0: недопустимый вход трактуется как «нет вхождений».

## Задача 4. Все индексы элемента

Дан массив из n целых чисел и число x. Найти все индексы элементов, равных x, в порядке возрастания. Требуется O(n).

### Идея решения

Используются два линейных прохода по массиву.
Первый проход подсчитывает количество элементов, равных `x` (аналогично задаче 3).
Второй проход заполняет массив индексов ровно нужного размера: при каждом совпадении текущий индекс записывается в результат.
Поскольку второй проход идёт слева направо, индексы автоматически оказываются в порядке возрастания.
Возвращается `int[]`; если вхождений нет (или массив `null`), возвращается пустой массив.
В `main` пустой результат выводится как `-1` — согласовано с задачей 2 («если не найдено — `-1`»), а непустой — как индексы через пробел.

### Асимптотика

[Расчет асимптотики задачи 4](asymptotics.md#задача-4-все-индексы-элемента).

Время: O(n).
Дополнительная память: O(k), где k — количество вхождений (для массива индексов). В худшем случае k = n, поэтому верхняя оценка — O(n).

### Проверки

- `5 9 4 9 2 7 5` → 1: одно вхождение.
- `5 4 4 9 4 2 4` → 0 2 4: три вхождения, индексы по возрастанию.
- `5 7 4 9 4 2 4` → -1: элемента нет.
- `4 6 6 6 6 6` → 0 1 2 3: все элементы равны.
- `1 25 25` → 0: один элемент, найден.
- `1 7 25` → -1: один элемент, не найден.
- `5 -8 -8 -14 -8 -2 -8` → 0 2 4: отрицательные числа.
- `7 5 -3 5 0 8 5 -7 5` → 1 4 6: смешанные знаки.
- `5 0 0 3 0 8 0` → 0 2 4: поиск нуля.
- `5 9 9 1 2 3 9` → 0 4: вхождения по краям.
- пустой массив → -1: нет вхождений.
- `null` → -1: нет вхождений.

## Задача 5. Сумма элементов на чётных позициях

Дан массив из n целых чисел. Найти сумму элементов с чётными индексами (0, 2, 4, …). Требуется O(n).

### Идея решения

Используется один линейный проход по массиву с шагом 2.
Счётчик `sum` инициализируется нулём, цикл `for (int i = 0; i < array.length; i += 2)` сразу перебирает только чётные индексы и прибавляет `array[i]` к сумме.
Проверка `i % 2 == 0` внутри цикла не нужна — шаг 2 её заменяет и вдвое сокращает число итераций.
Сумма накапливается в `long`, чтобы избежать переполнения `int` при больших значениях элементов.
Массив `null` и пустой массив дают `0` — по условию это сумма, а не признак «найдено/не найдено».

### Асимптотика

[Расчет асимптотики задачи 5](asymptotics.md#задача-5-сумма-элементов-на-чётных-позициях).

Время: O(n).
Дополнительная память: O(1) — только переменная sum.

### Проверки

- `5 4 9 2 7 5` → 11: индексы 0, 2, 4 → 4 + 2 + 5.
- `7 1 2 3 4 5 6 7` → 16: индексы 0, 2, 4, 6 → 1 + 3 + 5 + 7.
- `1 42` → 42: один элемент.
- `4 0 0 0 0` → 0: все нули.
- `5 -8 3 -14 6 -2` → -24: отрицательные числа.
- `5 -5 10 0 -3 7` → 2: смешанные знаки.
- `3 MAX 0 MAX` → 2 * MAX: проверка отсутствия переполнения int.
- `4 10 20 30 40` → 40: именно нулевая индексация (0, 2), а не «с первой позиции».
- пустой массив → 0: нет элементов.
- `null` → 0: нет элементов.

## Задача 6. Элементы больше среднего

Дан массив из n целых чисел. Найти количество элементов, строго больших среднего арифметического всех элементов. Гарантируется, что среднее — целое число (сумма делится на n). Требуется O(n).

### Идея решения

Используются два линейных прохода по массиву.
Первый проход вычисляет сумму всех элементов; сумма накапливается в `long`, чтобы избежать переполнения `int` при больших значениях.
Среднее вычисляется как `sum / n` — по гарантии условия деление целое.
Второй проход подсчитывает элементы, строго большие среднего: условие `value > average` (именно строгое, элементы, равные среднему, не считаются).
Массив `null` и пустой массив дают `0` — по условию возвращается количество, а не признак.

### Асимптотика

[Расчет асимптотики задачи 6](asymptotics.md#задача-6-элементы-больше-среднего).

Время: O(n).
Дополнительная память: O(1) — только sum, average и count.

### Проверки

- `5 5 1 9 2 8` → 2: сумма 25, среднее 5, строго больше — 9 и 8.
- `4 7 7 7 7` → 0: все равны среднему.
- `5 1 2 3 4 10` → 1: сумма 20, среднее 4, строго больше — только 10.
- `1 42` → 0: один элемент, среднее 42, строго больше нет.
- `4 -10 -4 -6 -8` → 2: сумма -28, среднее -7, строго больше — -4 и -6.
- `4 -4 0 4 8` → 2: сумма 8, среднее 2, строго больше — 4 и 8.
- `4 0 0 0 0` → 0: среднее 0, строго больше нет.
- `4 MAX MAX 0 0` → 2: проверка отсутствия переполнения int.
- `3 1 2 3` → 1: строгое неравенство — среднее 2, больше только 3 (а не 2 и 3).
- пустой массив → 0: нет элементов.
- `null` → 0: нет элементов.

## Задача 7. Второй максимум

Дан массив из n целых чисел, все элементы различны. Найти второй по величине элемент массива. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву.
Сначала сравниваются первые два элемента: больший становится `max`, меньший — `secondMax`. Это даёт корректную инициализацию без флагов и без `Integer.MIN_VALUE`.
Затем для каждого следующего элемента:
- если он больше `max` — старый `max` становится `secondMax`, а текущий — новым `max`;
- иначе, если он больше `secondMax` — обновляется `secondMax`.
  Ветка «элемент равен max» невозможна по условию (все элементы различны), поэтому не проверяется.
  Массив `null` и массив менее чем из двух элементов — некорректный вход, выбрасывается `IllegalArgumentException`.

### Асимптотика

[Расчет асимптотики задачи 7](asymptotics.md#задача-7-второй-максимум).

Время: O(n).
Дополнительная память: O(1) — только max и secondMax.

### Проверки

- `5 8 3 15 2 11` → 11: неотсортированный, max = 15.
- `5 15 3 8 2 11` → 11: максимум первый.
- `5 8 3 11 2 15` → 11: максимум последний.
- `5 1 3 5 7 9` → 7: отсортирован по возрастанию.
- `5 9 7 5 3 1` → 7: отсортирован по убыванию.
- `2 10 20` → 10: два элемента, возрастание.
- `2 20 10` → 10: два элемента, убывание.
- `4 -8 -14 -2 -6` → -6: отрицательные, max = -2.
- `5 -3 5 0 8 -7` → 5: смешанные знаки, max = 8.
- `3 -5 -10 -3` → -5: второй максимум отрицательный.
- `2 MIN 5` → MIN: Integer.MIN_VALUE — валидный второй максимум.
- `1 25` → исключение: один элемент, второго максимума нет.
- пустой массив → исключение: недопустимый вход.
- `null` → исключение: недопустимый вход.

## Задача 8. Фильтрация по знаку

Дан массив из n целых чисел. Разделить его на два массива — из положительных и из отрицательных элементов, сохраняя исходный порядок. Нули не включать ни в один из массивов. Требуется O(n).

### Идея решения

Используются два линейных прохода по массиву.
Первый проход подсчитывает количество положительных и отрицательных элементов.
Второй проход заполняет два массива ровно нужного размера: при `value > 0` элемент пишется в `positive`, при `value < 0` — в `negative`.
Нули не удовлетворяют ни одному условию, поэтому автоматически отбрасываются.
Поскольку второй проход идёт слева направо, исходный порядок сохраняется в обоих массивах.
Результат возвращается в виде неизменяемой пары `record FilterResult(int[] positive, int[] negative)`.
Массив `null` и пустой массив дают два пустых массива.

### Асимптотика

[Расчет асимптотики задачи 8](asymptotics.md#задача-8-фильтрация-по-знаку).

Время: O(n).
Дополнительная память: O(p + q), где p — число положительных, q — число отрицательных. В худшем случае p + q = n, поэтому верхняя оценка — O(n).

### Проверки

- `7 3 -1 0 7 -4 2 -9` → positive: `3 7 2`, negative: `-1 -4 -9`: смешанный массив, нули отброшены.
- `4 4 8 1 6` → positive: `4 8 1 6`, negative: `-`: только положительные.
- `4 -4 -8 -1 -6` → positive: `-`, negative: `-4 -8 -1 -6`: только отрицательные.
- `4 0 0 0 0` → positive: `-`, negative: `-`: все нули, оба массива пусты.
- `5 0 5 0 -3 0` → positive: `5`, negative: `-3`: нули в смешанном массиве.
- `1 25` → positive: `25`, negative: `-`: один положительный.
- `1 -25` → positive: `-`, negative: `-25`: один отрицательный.
- `1 0` → positive: `-`, negative: `-`: один ноль, ничего не включается.
- `7 9 -1 3 -2 7 -3 5` → positive: `9 3 7 5`, negative: `-1 -2 -3`: порядок положительных сохранён.
- `7 -9 1 -3 2 -7 3 -5` → positive: `1 2 3`, negative: `-9 -3 -7 -5`: порядок отрицательных сохранён.
- пустой массив → оба массива пусты.
- `null` → оба массива пусты.

## Задача 9. Проверка отсортированности

Дан массив из n целых чисел. Вывести YES, если массив неубывающий (a[i] <= a[i+1] для всех i), и NO иначе. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву с проверкой соседних элементов.
Для каждого i от 1 до n - 1 проверяется условие `array[i - 1] > array[i]`; если оно выполнено — порядок нарушен, сразу возвращается `false` (в `main` — `NO`).
Если цикл завершился без нарушений — массив неубывающий, возвращается `true` (`YES`).
Условие `>` (а не `>=`) принципиально: равные соседние элементы допустимы, потому что «неубывающий» — это `a[i] <= a[i+1]`, а не строго возрастающий.
Массив `null`, пустой массив и массив из одного элемента считаются неубывающими — тривиальные случаи.

### Асимптотика

[Расчет асимптотики задачи 9](asymptotics.md#задача-9-проверка-отсортированности).

Время: O(n).
Дополнительная память: O(1) — только счётчик цикла.

### Проверки

- `5 1 3 5 7 9` → YES: строго возрастающий.
- `6 1 2 2 5 5 9` → YES: неубывающий с дубликатами.
- `5 4 4 4 4 4` → YES: все элементы равны.
- `1 42` → YES: один элемент.
- `5 9 7 5 3 1` → NO: строго убывающий.
- `5 5 3 4 6 7` → NO: нарушение в начале.
- `5 1 2 3 4 2` → NO: нарушение в конце.
- `5 1 2 9 4 5` → NO: нарушение в середине.
- `5 3 1 4 2 5` → NO: произвольный неотсортированный.
- `6 -10 -5 -5 -1 0 3` → YES: отрицательные, неубывающий.
- `4 -3 -7 -1 -5` → NO: отрицательные, неотсортированный.
- `2 5 5` → YES: два равных элемента.
- `2 5 3` → NO: два элемента в неправильном порядке.
- пустой массив → YES: тривиальный случай.
- `null` → YES: тривиальный случай.

## Задача 10. Поиск элемента с условием

Дан массив из n целых чисел и число k (k ≠ 0). Найти индекс последнего элемента, кратного k. Если такого нет — вывести -1. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву **справа налево**.
Для каждого i от n - 1 до 0 проверяется условие `array[i] % k == 0`; при первом совпадении сразу возвращается индекс `i`.
Поскольку проход идёт с конца, первый найденный кратный элемент — это и есть последний в массиве.
Если цикл завершился без совпадений — возвращается `-1`.
Проверка кратности `value % k == 0` корректно работает и для отрицательных `value`, и для отрицательного `k`: в Java `-6 % 3 == 0`, `6 % -3 == 0`, `-6 % -3 == 0`. Отдельная обработка знаков не нужна.
Массив `null` трактуется как «элемент не найден» и даёт `-1`.
`k == 0` по условию запрещён, поэтому выбрасывается `IllegalArgumentException` — чтобы не получить `ArithmeticException` из `%` в глубине.

### Асимптотика

[Расчет асимптотики задачи 10](asymptotics.md#задача-10-поиск-элемента-с-условием).

Время: O(n).
Дополнительная память: O(1) — только счётчик цикла.

### Проверки

- `5 3 8 12 5 9 3` → 4: кратны 3 — индексы 0, 2, 4; последний 4.
- `5 4 9 2 7 5 3` → 1: единственное кратное.
- `4 6 12 18 24 6` → 3: все кратны 6, последний индекс 3.
- `5 4 9 2 7 5 11` → -1: кратных нет.
- `4 10 3 7 4 5` → 0: только первый элемент кратен 5.
- `5 -8 -14 -8 -2 -8 -2` → 4: отрицательные, все кратны -2, последний индекс 4.
- `5 3 8 12 5 9 -3` → 4: отрицательный делитель, последний кратный — 9 на индексе 4.
- `7 -3 5 0 8 5 -7 6 3` → 6: смешанные знаки, нуль кратен 3, последний кратный — 6.
- `5 0 3 0 8 0 7` → 4: нуль кратен любому k ≠ 0, последний индекс 4.
- `2 -2^31 5 -1` → 0: MIN_VALUE % -1 == 0 в Java, без переполнения.
- `3 1 2 3 0` → исключение: k = 0 запрещён условием.
- пустой массив → -1: нет элементов.
- `null` → -1: нет элементов.

## Задача 11. Ближайший к среднему

Дан массив из n целых чисел. Найти элемент, ближайший к среднему арифметическому. Если несколько — вывести первый по индексу. Среднее может быть дробным. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву.
Сначала вычисляется сумма всех элементов в `long`.
Затем для каждого элемента вычисляется расстояние до среднего. Чтобы избежать деления и погрешности `double`, сравниваются величины `|a[i] * n - sum|`: расстояние до `sum / n` пропорционально этой величине, а множитель `1/n` общий для всех элементов и на порядок не влияет.
Выбирается элемент с минимальной величиной `|a[i] * n - sum|`. Условие обновления — строгое `diff < bestDiff`, поэтому при равенстве сохраняется первый по индексу.
Массив `null` и пустой массив — некорректный вход, выбрасывается `IllegalArgumentException`.

### Асимптотика

[Расчет асимптотики задачи 11](asymptotics.md#задача-11-ближайший-к-среднему).

Время: O(n).
Дополнительная память: O(1) — только sum, best, bestDiff.

### Проверки

- `3 2 4 6` → 4: среднее 4, ровно элемент.
- `3 1 2 4` → 2: среднее 7/3 ≈ 2.333, ближе всего 2.
- `4 1 2 3 4` → 2: среднее 2.5, 2 и 3 равноудалены, ответ первый — 2.
- `2 -5 5` → -5: среднее 0, -5 и 5 равноудалены, ответ первый — -5.
- `1 7` → 7: один элемент.
- `4 3 3 3 3` → 3: все равны среднему.
- `3 -4 -1 0` → -1: среднее -5/3 ≈ -1.666, ближе всего -1.
- `5 -3 5 0 8 -7` → 0: среднее 0.6, ближе всего 0.
- `2 MAX MIN` → MAX: среднее -0.5, оба равноудалены, ответ первый — MAX.
- пустой массив → исключение: нет элемента.
- `null` → исключение: нет элемента.

## Задача 25. Сумма элементов

Дан массив из n целых чисел. Найти сумму всех элементов. Требуется O(n).

### Идея решения

Используется один линейный проход по массиву.
Переменная `sum` инициализируется нулём и имеет тип `long`: сумма `n` элементов может выйти за пределы `int` (например, `n * Integer.MAX_VALUE`), поэтому `int` недостаточно.
Для каждого элемента массива значение прибавляется к `sum`.
После прохода возвращается накопленная сумма.
Массив `null` и пустой массив дают `0` — по условию возвращается сумма, а не признак «найдено/не найдено».

### Асимптотика

[Расчет асимптотики задачи 25](asymptotics.md#задача-25-сумма-элементов).

Время: O(n).
Дополнительная память: O(1) — только переменная sum.

### Проверки

- `5 1 2 3 4 5` → 15: положительные числа.
- `4 -3 -7 -1 -5` → -16: отрицательные числа.
- `5 5 -3 2 -8 4` → 0: смешанные знаки, сумма 0.
- `1 42` → 42: один элемент.
- `4 0 0 0 0` → 0: все нули.
- `3 2^31-1 2^31-1 -2^31` → 2 * (2^31-1) + -2^31: граничные значения int.
- `2 2^31-1 2^31-1` → 2 * (2^31-1): проверка отсутствия переполнения int.
- пустой массив → 0: нет элементов.
- `null` → 0: нет элементов.
